# UI 規範（實作 Astro/Tailwind 時的唯一依據）

參考稿：`design/home.html`、`design/product.html`（用瀏覽器直接開）；token：`design/tokens.css`。Astro 元件要在視覺上對齊參考稿，不是重新設計。

## 設計立場
讀者是在手機上差一步就下單的人，介面要讓他「看懂、放心、點下去」。語彙取自家電的規格標示：記憶點只有一個——**到手價明細**（收據式：標價、折扣、補助、到手價，點線引導）。其餘保持安靜：邊線取代陰影、單一圓角、層級靠字重與留白。

## Token（見 tokens.css；Tailwind 對應）
- 把 `tokens.css` 的變數放進全域樣式，並在 Tailwind 的主題設定中對應成色彩名稱（`paper`、`surface`、`ink`、`ink-2`、`line`、`accent`、`promo`、`win`、`warn`）。設定檔寫法依 `npx astro add tailwind` 當時的官方做法為準（v3 與 v4 不同）。
- 深色模式跟隨系統（`prefers-color-scheme`），所有 token 都有深色值，不另做切換按鈕（第一階段）。
- 字體：系統中文字體堆疊，**不下載網路字型**（效能預算）。價格與數字一律 `tabular-nums`。
- 字階：14 / 16 / 18 / 22 / 30 / 40 px（中文內文 13–15px 偏小，2026-11-08 起內文提高到 16px）。內文行高 1.7，標題 1.3；中文標題不加負字距，標題 `text-wrap: balance`、段落 `text-wrap: pretty`、`line-break: strict`。行長 ≤ 34 個中文字（`max-w`）。
- 圓角只有 `10px`（卡片）與 `999px`（按鈕、標籤）。不使用陰影，用 `1px` 邊線。

## 元件清單與規則
| 元件 | 規則 |
|---|---|
| 到手價明細 `TotalCost` | 黑色頂線、點線引導、折扣與補助用 `promo` 色加負號、到手價最大字。桌機在右側欄黏住（sticky），手機接在 TL;DR 之後 |
| TL;DR | 一句話結論（22px 粗體）＋「適合／不適合」兩格＋「要先知道的缺點」（warn 底色），缺點不可省略 |
| 規格表 | 外層可橫滑、表頭 sticky、首欄 sticky；勝出格用 `win` 底色＋左側 3px 色條＋「勝出」文字（不只靠顏色） |
| 價格走勢 | 建置期內嵌 SVG，零 JS；資料不足時只顯示「資料累積中」 |
| `StickyCta`（手機） | 底部固定：到手價＋按鈕；到手價明細區的 CTA 進入視窗時隱藏，避免重複；桌機不顯示 |
| 商品卡 | 縮圖 4:3、型號、到手價（大）、標價（刪除線）、缺點一行。標籤用 `align-self: flex-start`，不要撐滿寬度 |
| 選購精靈 | 品類為橫向可捲動的膠囊；進度條 3 格；選項為大按鈕（≥48px 高） |
| 個人化問卷 `QuizDialog` | 原生 `<dialog>`，3 格進度條，選項大按鈕（≥52px），有「先跳過」與「上一題」；只自動跳出一次 |
| 畫像列 `ProfileBar` | 以 chip 顯示系統記住的條件（有貓／有小孩／空間大小），旁有「修改」「清除資料」 |
| 搜尋與「我的理解」 | 搜尋框 48px 圓角；下方用 chip 顯示解析結果；命中理由用 `win` chip |
| 購買意圖抽屜 `IntentDrawer` | 手機：底部抽屜（上緣 4px `accent` 色條、安全區留白）；桌機：右下角卡片。內含一行文案＋兩個等寬 CTA（蝦皮／酷澎，副標「標價較低／較快到貨」僅在資料支持時出現）＋一行小字註明以平台頁面為準。只用 transform/opacity 過渡、`role="status"`、有關閉鈕；顯示時 StickyCta 讓位 |
| 情境頁 | 與商品頁同樣的 token；導言＋2–4 張比較卡（缺點必顯示）＋FAQ；不做新樣式 |
| `InAppWarning` | 頂部 sticky，深色底，按鈕 `nowrap` |
| FAQ | 原生 `<details>`，零 JS |

## 文案規則
- 按鈕寫明確動作：「到蝦皮看最新價格」「到酷澎看最新價格」，不寫「立即搶購」。
- 標題與標籤用一般句式，不用全大寫小標、不用箭頭按鈕、不用編號裝飾（內容不是步驟時）。
- 不出現沒有資料支持的說法（「最多人選」「最低價」「限時」），資料不足就說資料不足。

## 視覺 QA（每個頁面類型做一次，Step 4、Step 5、Step 8）
1. 執行 `npm run dev`，另開終端機：`node scripts/screenshot.mjs http://localhost:4321/ reports/shots/home`（需先 `npm i -D playwright && npx playwright install chromium`；沒有就用瀏覽器開發者工具手動截圖 390px 與 1280px、淺色與深色）。
2. 並排比對 `design/` 參考稿，逐項檢查：無橫向捲動、桌機有右側明細欄、手機有底部 CTA、勝出格清楚、深色模式對比足夠、焦點外框可見。
3. 有差異就改，直到一致；請使用者目視確認後才通過。
