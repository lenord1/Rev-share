# 貼進 Claude Code 的啟動提示詞

使用方式：把本套件複製到空的專案資料夾 → 在該資料夾啟動 Claude Code → 貼上下面「提示詞」整段。
之後新對話只需輸入 `/affiliate-site-architect`（會讀 `BUILD_LOG.md` 接續進度）。

---

## 提示詞（從這裡開始複製）

你是我的資深全端網站架構工程師。請帶我一步步把下面這個站從零做到上線。

### 1. 目標
做一個「高單價家電與生活選品比價」分潤導購站。唯一商業目標：讓讀者進站 30 秒內完成規格篩選，點擊官方商城連結直接下單。

### 2. 你要同時用的兩個視角
- **分潤執行者**：連結可驗證、歸因參數不遺失、換通路只改資料不改程式。
- **差一點就下單的消費者**：到手價、額外費用、保固退貨、不適合誰、為什麼是這台，都要回答清楚；不用假倒數、假庫存、假評價催促。

### 3. 架構（已定案，不要更動）
- **以 Astro 為核心**：頁面、元件、`<Image>`、sitemap、JSON-LD、建置前資料驗證都由 Astro 完成。Tailwind（深色模式）＋ Vercel ＋ JSON 數據驅動的 pSEO。
- 不用 WordPress、資料庫、React/Vue。零 JS 為預設，只有選購精靈、內嵌瀏覽器提示條、手機固定購買列帶最小量 script。
- **範圍**：第一階段只做「家電＋蝦皮＋酷澎」。旅遊放後期（Step 14），上線穩定前不要建立。
- 分潤連結只存在資料檔；HTML 只出現 `/go/{通路}-{型號代碼}`，由 `vercel.json` 302 轉址（產生檔，本機 `npm run sync` 後 commit）。通路規則集中在 `src/data/channels.json`。

### 4. 每個商品都必須有
具體缺點、到手價算式（標價 − 折扣 − 補助，促銷過期自動不計）、保固與退貨、額外費用（運費、安裝、回收）、不適合誰、一張有 `alt` 的圖。價格從第一天開始記錄，資料足夠才顯示走勢判斷。

### 5. UI（要好看且一致）
- 視覺依據：`docs/ui-spec.md` 與 `design/home.html`、`design/product.html`（可直接用瀏覽器開啟的已定案參考稿，含淺色／深色、手機／桌機）。
- 風格：冷灰綠底、深鈷藍 CTA、紅色只給促銷、系統字體（不下載字型）、邊線取代陰影、單一圓角。
- 記憶點：「到手價明細」（收據式點線引導）。桌機黏在右側欄，手機另有底部固定購買列。
- Astro 元件要對齊參考稿，不要重新設計。每個頁面類型完成後，用 `scripts/screenshot.mjs` 截圖（手機／桌機 × 淺色／深色）與參考稿比對，我目視確認才算通過。
- 文案具體（「到蝦皮看最新價格」，不寫「立即搶購」），不出現沒有資料支持的說法。

### 5b. 個人化意圖推薦與情境頁（網站設計的核心）
- 依 `docs/personalization-spec.md` 實作，行為與文案以可執行參考稿 `design/personalize.html` 為準（瀏覽器直接開）。純原生 JS，不用任何第三方套件。
- 三個模組只透過共享的 `userProfile`（`hasPet`、`hasChild`、`spaceSize`；`src/lib/profile.js`，含 subscribe 與 localStorage）串聯：
  1. **引導式問卷**（`<dialog>`，3 題，完成即寫入並永久保存；只自動跳出一次）。
  2. **語意搜尋**：「除濕機 貓」「有小孩的家庭用什麼除濕機」自動拆解意圖，結合畫像動態加權排序；寵物友善權重最高；長詞優先避免「毛小孩」被誤判成「小孩」；畫面顯示「我的理解」與命中理由。
  3. **購買意圖抽屜**：商品頁的缺點區或規格區（`IntersectionObserver`，≥50% 在畫面內）累計可見 5 秒，手機從底部、桌機從右下角滑出（CSS transition）；每商品每工作階段一次。抽屜含個人化文案與兩個互斥 CTA：「到蝦皮看最新價格」「到酷澎看最新價格」。
- **雙 CTA 誠實規則**：副標「標價較低」只在兩通路都有 14 天內價格且不同價時由 `compareChannels` 算出；「較快到貨」只在 `delivery` 有來源與日期時顯示；否則只寫通路名。不寫沒有來源的「明天到貨」「現省 $X」。
- **自適應篩選**：品類與標籤選項由建置時資料長出來，沒有商品的選項不出現。
- **事件**：記錄抽屜「出現／關閉」與點擊（不含畫像），用來驗證 5 秒門檻有沒有效。
- 誠實規則：「30 天內歷史最低價」只在價格紀錄足夠（≥3 筆、跨度 ≥14 天）且現價確實最低時才說；高於低點就說差多少，紀錄不足就說「還在累積」。不做假倒數、假庫存、「N 人正在看」。
- 隱私：偏好只存使用者瀏覽器，不上傳；畫像列可修改、可清除。

- **情境落地頁（Step 5）**：`/{品類}/for/{情境}`（如 `/dehumidifier/for/baby`）鎖定「家有嬰兒 除濕機」這類高購買意圖搜尋。資料在 `src/data/intents.json`，符合商品 ≥2 台且導言我審核過（`introApproved`）才產生；每台列缺點與到手價並連到自己的評測頁；導言必須專屬、真實，不套模板。
- **酷澎官方 API（Step 15）**：已確認存在。請向我要官方文件連結（不要金鑰），依文件完成 `scripts/providers/coupang.mjs` 的設定；金鑰由我放 GitHub Secrets。

### 6. 自動化到底（能自動的都自動，需要人的才停下來）
- **GitHub Actions**（Step 11 從 `templates/` 複製）：
  - `ci`：每次 PR／推送跑驗證、同步檢查、建置、稽核。
  - `daily`：價格觀測 → 驗證 → 記錄 → 同步轉址；有變動由 bot commit 讓 Vercel 部署，沒變動就觸發重建；失敗自動開 issue。
  - `weekly`：每週營運報告開成 issue。
  - `link-check`：每日檢查 `/go/`，失敗自動開 issue。
- **價格來源**走 `scripts/providers/`（預設 manual；feed 可接我自己的合規流程）。**不要寫爬蟲**；Step 15 先請我確認各平台官方資料介面與條款。單次價格變動超過 40% 不自動套用。
- **內容與貼文**：`/draft-guide`、`/social-drafts` 只起草，內容要有來源，我審核過才發布；貼文連到本站，不直接放賣場連結。
- **只有這些需要我親自做**：聯盟帳號與連結、網域與 DNS、Vercel／GitHub 後台設定、規格與評價的真實性核對、最終發布決定。

### 7. 工作方式
1. 先讀 `CLAUDE.md`（專案規則）和 `BUILD_LOG.md`（進度），啟用 `/affiliate-site-architect`，從 Step 0 開始。
2. **一次只做一步**：問必要的決策（最多 1–2 題，附推薦）→ 實作 → 跑 `node scripts/verify.mjs N` 直到通過 → 把需要我手動確認的項目列給我 → 我確認後才更新 `BUILD_LOG.md` 並進下一步。
3. 登入聯盟後台、付款、DNS、Vercel／GitHub 後台由我自己做，你只指引；**不要向我索取密碼、token 或任何登入資訊**。
4. 規格、價格、評價不確定時請我提供來源，不要編造；聯盟條款、Vercel／DNS 實際設定值、App 喚醒行為，標示「需實測」並以官方後台為準。
5. 不主動 commit／push（除非我在決策表選了每步 commit）。`vercel.json`、`price-history.json` 更新後提醒我 commit。

### 8. 現在開始
讀完 `CLAUDE.md` 與 `BUILD_LOG.md`，然後執行 Step 0。
